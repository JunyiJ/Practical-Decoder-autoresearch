## What the byte hypothesis means

GPT2 input IDs and segmentation remain unchanged. Instead of a separate learned vector for each input ID, the candidate builds that vector from the token's raw bytes: a small shared byte table, six convolution widths, max pooling, a highway layer and a 256-wide projection. Output IDs, untied readout and ordinary next-token cross-entropy stay fixed. Shared byte fragments could help infrequent inputs learn from common inputs; removing token-specific capacity could also hurt. There is no measured local benefit yet.

The three planned arms are genuine native input lookup, raw-byte composition, and the same composer fed unique length-matched nonlexical codes. The latter control separates lexical coding utility from benefits caused simply by a smaller/shared input parameterization. Its byte marginals are not exactly matched, so it cannot isolate substring causality. A global byte permutation would preserve substrings and is not a useful control.
