## Training-prefix initialization and lineage

Read UTF-8 with the same universal-newline handling as TinyDataLoader. Preserve its existing sorted global character alphabet, which is constructed from the full corpus; disclose that existing vocabulary construction. Count token occurrences only in the training prefix ending at `int(0.8 * token_count)`. Do not use validation/test frequencies, losses or scores for initialization. Prefix frequencies are not claimed to be exactly the paired-block sampler's target frequencies.

For vocabulary size V and counts c, compute `u_i = log((c_i + 1)/(sum(c) + V))` and subtract the arithmetic mean of u. Laplace pseudocount1 is fixed, with no tuning. All arms bind the same corpus-byte SHA, tokenizer/order, token count, split boundaries, count vector/hash and centered initialization/hash. The trainer checks the declaration against the actual loader vocabulary and training tokens before constructing GPT. The request API's vocabulary-size placeholder is replaced by the actual loader vocabulary before this check. No validation or test batches are sampled by the prior builder.

The two learned arms add V FP32 scalars, created after shared weight initialization without random draws. Their optimizer is AdamW at base LR, with the same independent per-update decay and zero inner weight decay. Hidden matrices retain their existing Muon width factors. H200 includes these learned scalars. The prior vector is after width division, so its initialization is width-independent for a fixed vocabulary. This algebra is not an empirical optimal muP claim.

Explicit `mha4_train_bound_output_bias` binds kind and full prior alongside inherited input/final-norm contracts. Saved/current/constructed semantic signatures must match even for zero/unigram variants with identical shapes. Reject config deletion or mutation that hides a changed prior. Defaults preserve old state keys, RNG and arithmetic. Actual tests must establish shared initialization, parameter counts, independent forward/gradient formulas, cache causality, optimizer roles, private sampler RNG, passive averaging, exact CPU resume and inference/resume rejection.

A centered log prior is not a claim that the initial contextual model predicts exactly unigram probabilities. Learned-zero versus none changes parameterization; unigram versus zero tests initialization within that parameterization. Unigram versus none combines both. Selected-recipe contrasts include independently tuned LR. Do not attribute a mechanism or unigram advantage without examining the direct unigram-minus-zero contrast. That diagnostic contrast is reported but is not a hidden extra adoption gate.
